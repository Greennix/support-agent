# support-agent

基于 RAG 与工具调用的企业售后工单 Agent，面向规则检索、订单查询和确认后建单场景。

本项目用于学习和实践 AI Agent 应用开发，业务文档、订单和工单均使用自建模拟数据。仓库只存放 Agent 项目，Python 基础练习单独维护。

详细功能、业务规则、接口和验收要求见 [项目需求说明](docs/项目需求说明.md)。

> 当前处于项目初始化阶段：Git 仓库、Python 忽略规则和本地独立虚拟环境已就绪。业务接口、RAG 和 Agent 功能将按下方路线逐步实现，目前尚无可运行的业务服务或评测结果。

## 业务场景

用户提出：

> 帮我查询订单 O1001 是否符合售后规则。如果符合，先生成工单草稿，等我确认后再提交。

目标处理流程：

1. 检索适用的售后规则，保留文档来源和版本。
2. 查询当前用户有权访问的模拟订单。
3. 根据规则与订单信息生成建议；缺少信息时先澄清。
4. 生成工单草稿，等待用户确认或拒绝。
5. 服务端校验身份、草稿和确认状态后创建工单。
6. 返回处理结果、规则引用和工单编号，并保留执行记录。

## 计划功能

- [ ] **模型调用**：统一调用接口、超时处理、结构化输出、流式响应和 Token 用量记录。
- [ ] **知识库问答**：文档清洗、分块、Embedding、检索、重排、来源引用与无答案拒答。
- [ ] **订单工具**：参数校验、模拟订单查询和服务端访问权限检查。
- [ ] **业务 Agent**：先实现受限工具循环，再接入图编排；限制可用工具、执行步数和调用预算。
- [ ] **确认与恢复**：工单草稿、人工确认、幂等建单、状态持久化和中断恢复。
- [ ] **MCP 扩展**：通过最小只读服务练习工具发现与订单查询。
- [ ] **评估与追踪**：固定评测集、任务终态检查、阶段耗时、工具记录和失败案例分析。
- [ ] **部署与演示**：可复现启动步骤、最小容器部署和完整业务演示。

## 技术路线

下表为计划选型。当前本地仅配置了 Python 3.14.8 和虚拟环境，项目依赖将在接入时验证兼容性并锁定版本。

| 模块 | 计划方案 |
| --- | --- |
| 开发语言 | Python 3.14 |
| API 与数据校验 | FastAPI、Pydantic |
| 模型能力 | 可稳定访问的模型 API；分别确认对话、工具调用、Embedding 与 Rerank 能力 |
| 检索 | NumPy 精确检索基线，逐步接入 Qdrant、BM25、RRF 与 Rerank 对照实验 |
| Agent 编排 | 手写工具循环 → LangGraph |
| 业务数据与状态 | SQLite；持久化订单、工单及必要执行状态 |
| 工具协议 | MCP Python SDK 的最小只读集成 |
| 测试与运行 | pytest、结构化日志，后续补充 Docker Compose |

### 核心工具设计

| 工具 | 用途 | 执行约束 |
| --- | --- | --- |
| `search_knowledge` | 检索售后规则并返回来源片段 | 按用户权限、知识范围和规则版本过滤 |
| `query_order` | 查询模拟订单 | 身份由服务端确定，仅返回有权访问的订单 |
| `create_ticket` | 将已确认草稿转为工单 | 校验用户确认；使用幂等键避免重复建单 |

模型可以提出工具调用请求，实际执行前的身份、参数、确认和幂等校验由服务端代码负责。

## 本地开发环境

### 1. 获取项目

首次下载项目：

```bash
git clone https://github.com/Greennix/support-agent.git
cd support-agent
```

已有本地仓库时，直接进入该仓库目录。

### 2. 创建独立虚拟环境

先确认本机已有可用的 Python 3.14：

```bash
python3.14 --version
```

首次配置项目时创建环境：

```bash
python3.14 -m venv .venv
```

本地已经创建过 `.venv` 时，无需重复创建，直接激活。

### 3. 激活并验证

macOS / Linux：

```bash
source .venv/bin/activate
python --version
python -m pip --version
```

确认使用的是当前项目内的解释器：

```bash
python -c "import sys; print(sys.executable)"
```

输出路径应位于当前项目的 `.venv/bin/` 下。IDE 中也应选择该解释器。

退出虚拟环境：

```bash
deactivate
```

### 4. 依赖与运行入口

项目初始化阶段尚未添加依赖清单、API 入口或启动命令。引入业务代码时，将同步补充锁定的依赖版本、配置示例和实际可执行的运行步骤。

本地 `.venv` 不提交到 Git；其他开发者使用自己的 Python 安装重新创建环境。后续模型配置使用本地环境变量，配置示例仅保留字段和占位值。

## 验收与评估方向

后续将建立独立的 RAG 与 Agent 场景集，保存配置、原始输出及失败原因。以下为评估设计，目前没有实测结果。

- **检索效果**：记录明确口径的 Hit@K、Recall@K、MRR，并对比不同检索配置。
- **回答质量**：检查结论、关键条件和引用是否有证据支持；无答案时是否正确拒答或澄清。
- **任务完成**：检查期望业务终态、工具执行记录和数据库结果。
- **业务约束**：覆盖越权查询、未确认写入、重复提交和中断恢复。
- **运行表现**：记录首内容延迟、总耗时、错误率及可获取的 Token 用量。

开发集用于调参，留出集用于独立检查；已经依据留出结果修改系统后的复测，应标注为回归评测。最终报告写明样本量、运行环境和局限。
